# āvuso → «товарищ»: канонические правила

Область: только **MN** (`dhammagift/translation/ru/sutta/mn`).
Пали: `āvuso` в `sc_bilara_data/root/pli/ms`.
Русский источник: «друг/друзья». Цель: «товарищ/товарищи».

## 1. Главное правило

«Товарищ» всегда стоит **после** имени/обращения и отделяется запятой:

- `Калама, товарищ`
- `Сарипутта, товарищ`
- `Монахи, товарищи`

Запрещено:

- `Товарищ Калама`
- `Товарищи монахи`
- `Сарипутта товарищ` — без запятой
- `Имятоварищ` — слитное написание

## 2. REPLACE

Если в RU уже есть «друг/друзья»:

- `друг` → `товарищ`
- `друзья` → `товарищи`
- при имени/существительном — инверсия:
  - `друг Сарипутта` → `Сарипутта, товарищ`
  - `друзья монахи` → `Монахи, товарищи`

Число:

- один собеседник, имя в ед. ч., «ты» → `товарищ`;
- несколько собеседников, «вы», `монахи`, `Нигантхи` → `товарищи`;
- обращение к группе — в постпозиции: `Монахи, товарищи`.

Имя:

- можно добавить **одно** имя с заглавной, если оно есть в пали, а в RU опущено:
  `Друзья` → `Нигантхи, товарищи`;
- имя с маленькой буквы (`нигантхи`) автоматически не принимается — нужна ручная правка.

## 3. INSERT (пропущенный āvuso)

Если в RU обращения нет, но в пали `āvuso` есть:

- `anchor_before` — точная подстрока до места вставки;
- `anchor_after` — точная подстрока после;
- `insert` — `Имя, товарищ` / `товарищ` / `товарищи`;
- итог: `anchor_before, insert, anchor_after`.

Пример:

```
PALI: Seyyathāpi, āvuso moggallāna, rañño vā ...
RU:   Это как если бы у царского министра был полный сундук...
→ anchor_before="Это как", anchor_after="если бы",
  insert="Моггаллана, товарищ"
→ «Это как, Моггаллана, товарищ, если бы у царского министра...»
```

Не ставить обращение в начало, если в пали оно не в начале.
Не дублировать, если «товарищ» уже есть.

## 4. Пунктуация и кавычки

- запятая после имени и после обращения, если фраза продолжается:
  `Имя, товарищ, ...`;
- не допускать `“,`, `, .`, `,,`, пробел перед `, . ; : ! ?`;
- кавычки прямых речей не ломать; лишние кавычки/запятые внутри реплик убирать;
- группа: `Монахи, товарищи!` (не `Товарищи монахи!`).

## 5. KEEP и спорные

`keep` / «Спорные моменты», если:

- в RU уже есть «товарищ/товарищи»;
- RU пустой;
- уверенность < 0.6;
- замена/вставка не проходит валидацию;
- якоря не найдены или не уникальны.

Спорные **не** применяются в ветку.

## 6. Валидация (`work/apply_edits.py`)

`replace`:

- `old` есть в RU и уникален;
- `source` — форма с леммой «друг»;
- `target` — форма с леммой «товарищ»;
- после удаления всех source/target остальные слова совпадают (порядок может меняться);
- пунктуация, кроме запятых, та же (запятые можно добавлять по правилу постпозиции);
- допускается одно добавленное имя с заглавной (`allow_name_addition`);
- `confidence >= 0.75`.

`insert`:

- `anchor_before + anchor_after` встречается в RU ровно так;
- `insert` содержит «товарищ»;
- итог = `anchor_before`, `insert`, `anchor_after` с корректной запятой;
- нет дублирования.

Ручные правки:

- `work/insertions.yaml` — `insert` / `replace` / `keep` / `skip`;
- `work/manual-fixes.yaml` — точечные post-фиксы;
- `work/normalize_comrades.py` — постпозиция и запятые по всем MN.

## 8. История

Ранние примеры в промпте были без запятой (`Сарипутта товарищ`,
`Моггаллана товарищ`). Актуальное правило — **с запятой**:
`Сарипутта, товарищ`, `Моггаллана, товарищ`. Старые результаты
ретроспективно нормализуются `normalize_comrades.py`.
